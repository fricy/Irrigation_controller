## System Overview

Automated irrigation system with up to 15 independent zones (7/11/15 zone variants), local control via 3 buttons and OLED display, remote control via Zigbee (Home Assistant / Zigbee2MQTT). WiFi/HA native API available as secondary interface.

### Key Features
- 7, 11, or 15 irrigation zones (compile-time substitution)
- 3 operating modes: Irrigation cycle, Short cycle, Manual zone
- Zigbee endpoints: N zone switches + 2 cycle triggers (EP16/17) + 1 global config/status (EP18)
- Local control: 3-button + 128×128 OLED with full settings UI
- Power loss recovery with unified boot decision tree (missed cycle detection, queue restore)
- Cycle queue: one pending cycle survives power loss and resumes after active cycle ends
- Pump sequencing: configurable start/stop offsets and inter-zone switch delay
- Duration scaling: seasonal multiplier with timed auto-reset, per-cycle-type enable
- Cycle repeat: 1-3 passes (stored 0-2, displayed 1-3)
- DS3231 RTC: primary time source; Zigbee updates RTC hardware
- Screensaver / night-off display burn-in protection
- Maintenance lock: blocks all cycle/zone starts via device or ZB
- Overwatering protection: zone_start_counter limits powerloss-resume attempts per zone
- Scale=0% protection: invalid cycles discarded in decision tree before display or resume
- English/Hungarian UI localisation (compile-time substitution)

### WS2812 RGB States
| Priority | Condition              | Pattern                   |
| -------- | ---------------------- | ------------------------- |
| 1        | Fault page active      | Red blink 2s on/off       |
| 2        | Power loss page active | Green/blue alternating 2s |
| 3        | Cycle paused           | Green blink 2s on/off     |
| 4        | Pump lockout           | Solid red                 |
| 5        | Pump running           | Solid green               |
| 6        | Idle                   | Solid blue                |
- RGB led is set to 50% brightness.

### Button LED Patterns
- **Baseline**: all LEDs ON (restore_mode: ALWAYS_ON)
- **Any push**: LED OFF on press, ON on release (< 1000ms)
- **Medium push (all buttons)**: LED turns ON at 1000ms threshold
- **Long push (B1 only)**: LED pulses 500ms OFF/ON at 5000ms threshold
- **Cycle start**: B2+B3 LEDs: OFF→ON sequential 500ms each
- **Cycle end**: all LEDs OFF 500ms, ON 500ms, OFF 500ms, ON
- **Zone transition**: B2+B3 OFF, 500ms B2 ON, 500ms B3 ON

### Zone Configuration
- `TOTAL_ZONE_COUNT` and `CYCLE_ZONE_COUNT` defined in `zones/zone_config_N.h`
- 11-zone build: zone 11 is set to manual-only; `CYCLE_ZONE_COUNT=10`
- 7-zone and 15-zone builds: all zones participate in cycles
- Zone names defined in `zone_config_N.h` `zone_name()` function
- Default: irr=15min, short=10min, manual=20min, flags=0x03 (both enabled)

### Zone Duration Accessors
`zone_irr_duration_sec(zone_num)` and `zone_short_duration_sec(zone_num)` in `helpers.h` apply both `duration_scale_percent` and `scale_enable` filtering. Return 0 for zones where scale or enable prevents running.

- `maintenance_lock=1` blocks all cycle/zone starts
- Linked to `irrigation_allowed` binary sensor (inverse)
- ZB attr `zb_maintenance_lock` (0x000C)
- `PAGE_PUMP_FAULT` with maintenance sub-page; B2 clears lock

### Scale Enable
- `scale_enable=1`: only irrigation durations scaled
- `scale_enable=2`: only short durations scaled
- `scale_enable=3` (default): both scaled

## Zigbee Integration

### Endpoint Map
| EP  | Cluster         | Function                                                  |
| --- | --------------- | --------------------------------------------------------- |
| 1-N | ON_OFF + 0xFFF0 | Zone switch + per-zone config (N = zone count)            |
| 16  | ON_OFF + 0xFFF1 | Irrigation cycle trigger + 2 schedules (EP16 for 11-zone) |
| 17  | ON_OFF + 0xFFF1 | Short cycle trigger + 2 schedules (EP17 for 11-zone)      |
| 18  | 0xFFF2          | Device globals: config RW + runtime RO (EP18 for 11-zone) |

Zone EP count determines global EP numbers. Z2M converter auto-detects via cluster 0xFFF0.

### Cycle EP ON/OFF (EP N+1 / N+2) Behaviour
- **ON**: start cycle if idle; queue if busy
- **OFF (matching running cycle)**: abort cycle
- **OFF (matching queued cycle)**: clear queue
- **OFF (neither)**: ignored
- State pushed via explicit `setAttr`/`reportAttr` on named attrs `irr_onoff`/`short_onoff` (no APS binding — `set_report(false)` in generated code, binding would consume table slots)

### EP Custom Cluster 0xFFF0 (per zone, attrs 0x0001-0x0004)
| Attr | Name | Notes |
|------|------|-------|
| 0x0001 | irr_duration | minutes (0=disabled) |
| 0x0002 | short_duration | minutes |
| 0x0003 | manual_duration | minutes |
| 0x0004 | flags | bit0=irr_enabled, bit1=short_enabled |

### APS Binding Table
- Default 16 slots. Zone EPs only bound in `configure()` (not cycle EPs).
- 11-zone: 11 slots used. 15-zone: 15 slots used (1 spare). Max zones without SDK edit: 15.
- Cycle EP state pushed explicitly via `zb_push_cycle_genOnOff` script.

### Z2M Converter
- ESM `.mjs`, Z2M ≥ 2.9.2
- Auto-detects zone count from eps with cluster 0xFFF0; caches per IEEE address
- `configure()`: EP N+3 (global) read first; zone EPs bound genOnOff; cycle EPs NOT bound
- Naming: `ctrl_*` controls, `cycle_*` config, `manual_*` durations, `status_*` RO runtime, `zb_*` device config
- `fzGlobal` handles `zb_reboot=false` and `zb_skip=false` reports (UI self-reset)

## Operating Modes

### Irrigation Cycle
- Runs all zones where `zone_irr_duration_sec(i) > 0` (respects scale + scale_enable)
- `current_cycle_num = 1`, ZB trigger: EP N+1 ON

### Short Cycle
- Same zone sequence with independent durations; no daily-run check
- `current_cycle_num = 2`, ZB trigger: EP N+2 ON

### Manual Zone
- Single zone for configurable duration; live B2/B3 adjustment
- Manual durations NOT scaled
- `current_cycle_num = 0`, ZB trigger: EP 1-N ON (when idle)

## Cycle Execution

### Zone Sequencing
1. `start_cycle_actual(cn)`: validates `zone_queue_size > 0` BEFORE writing NVS state
2. `start_next_zone_in_cycle`: finds next enabled zone; resets `zone_start_counter`
3. First zone: opens relay + starts pump via `pump_start_sequence`
4. Subsequent zones: `zone_switch_delay_script` → closes old, delay, opens new
5. `zone_countdown_timer` decrements `zone_remaining_sec` and `cycle_remaining_sec`
6. At last zone: cycle end pattern → pump stop → lockout → `start_queued_cycle_script`

### Cycle Repeat
- `cycle_repeat_count` stored 0-2 (displayed 1-3): extra passes after first completion
- `cycle_repeat_remaining` persisted via `saved_repeat_remaining`

### Abort
- `abort_cycle_script`: stops all relays, pump stop sequence, lockout, resets globals
- Clears `saved_cycle_type=0`, `zone_start_counter=0`

---

## Pump Sequencing

### Start Offset (pump_start_offset, -5..+5s)
- Positive: valve opens first, pump starts N seconds later (low-pressure start)
- Negative: pump starts first, valve opens N seconds later

### Stop Offset (pump_stop_offset, -5..+5s)
- Positive: pump stops first, valve closes N seconds later (pressure bleeds)
- Negative: valve closes first, pump stops N seconds later

### Zone Switch Delay (zone_switch_delay_sec, 0-5s)
- Delay between closing one zone valve and opening the next
- Applies during normal zone transitions and inter-repeat boundaries

### Pump Lockout
- `pump_lockout_sec` mandatory wait after any cycle end
- Skip lockout via B1 on PAGE_LOCKOUT: clears lockout, pushes ZB lockout state, updates RGB, restarts queued cycle
- Fires `start_queued_cycle_script` on natural completion

## Power Loss Recovery

### Unified `do_start` Contract
Both auto-resume and manual-confirm paths go through `do_start(pending_type, pending_zone, resume)`:
1. Validates zone count: if no valid zones (scale=0% or scale_enable mismatch) → silently skip
2. Sets identical ZB state regardless of branch: EP cycle genOnOff, `zb_cycle_state`, `zb_active_zone`, `zb_pause`
3. Auto-resume (`auto_resume_on_powerloss=true`): 2s delay via `auto_resume_delay`, then `powerloss_resume` or `start_*_actual`
4. Manual-confirm (`auto_resume_on_powerloss=false`): shows `PAGE_POWERLOSS`, waits for B3

The 2s delay on auto-resume allows the OLED driver to initialize before `PAGE_CYCLE_RUNNING` is rendered.

### Boot Decision Tree
Triggered by whichever fires first: RTC valid at boot, ZB time sync, NVS seed, or 30s hard timeout. Guarded by `boot_decision_ran` (runs once per boot).

**Pre-validation (before decision matrix):**
- Discard interrupted cycle with `saved_zone_num=0` (aborted before any zone started)
- Discard missed c1 if no valid zones (scale=0% or scale_enable mismatch)
- Discard missed c2 if no valid zones

**Decision Matrix:**
| Interrupted | Missed c1 | Missed c2 | Queued | Action |
|-------------|-----------|-----------|--------|--------|
| 0 | 0 | 0 | 0 | Case 1: idle boot |
| 1 | 0 | 0 | 0 | Case 5: resume interrupted |
| 1 | 0 | 0 | Q | Case 5: resume interrupted, queue Q |
| 0 | 1 | 0 | — | Case 3: fresh c1, clear all |
| 0 | 0 | 1 | — | Case 4c: fresh c2, clear interrupted |
| 0 | 1 | 1 | — | Case 3: c1 wins |
| 1 | 1 | 0 | — | Case 4b: fresh c1, queue interrupted |
| 1 | 0 | 1 | — | Case 4b: resume interrupted, queue c2 |
| 1 | 1 | 1 | — | Case 3: fresh c1, queue interrupted |

### Saved State Globals (restore_value: yes)
- `saved_cycle_type`, `saved_zone_num`, `saved_repeat_remaining`
- `queued_cycle_num`: persists queue across power loss
- `zone_start_counter`: overwatering protection counter (see Safety Features)

### `powerloss_resume` Zone Resolution
Single-pass `while` loop (no recursion) resolves the starting zone:
1. Check `zone_start_counter ≥ 3` → reset counter, force zero-duration (triggers skip)
2. Check zone duration = 0 (scale=0% or disabled) → find next valid zone
3. If no next zone in pass → check repeats; if repeats remain restart from zone 1; else abort cleanly
4. Break when valid zone found; increment counter and resume

### `zb_push_boot_status` Stale Cleanup
- Uses `current_zone_num` if `cycle_running` (auto-resume already started) to avoid zeroing active zone
- Cycle genOnOff only cleared if `!cycle_running`
- 3s authoritative push dispatches to:
  - `zb_push_cycle_start` if `cycle_running`
  - `zb_push_powerloss_pending` if `power_loss_detected`
  - `zb_push_cycle_stop` otherwise

## Cycle Queue

- `queued_cycle_num` (restore_value: yes): 0=none, 1=irr, 2=short
- c1 overwrites c2; c2 does NOT overwrite c1 (irrigation has priority)
- Queue populated when busy: `cycle_running`, `cycle_paused`, `power_loss_detected`
- Queue consumed by `start_queued_cycle_script` after cycle end, lockout end, manual zone end
- `zb_queue_state` (0x0010): pushed on all queue state changes

---

## Duration Scale & Timed Reset

- `duration_scale_percent`: 0 or 10-200 in 10% steps; 0=skip all zones
- Applied via `zone_irr_duration_sec()` / `zone_short_duration_sec()` accessors
- `scale_enable`: controls which cycle types are affected (1=irr, 2=short, 3=both)
- Timed reset: `scale_reset_days` days after origin, scale resets toward 100%
- `scale_reset_day_counter` and `scale_reset_origin` persisted (restore_value: yes)
- Scale=0% protection: cycles with no valid zones discarded at `do_start` and in decision tree

## Time & Scheduling

### Time Source Priority
1. **DS3231 RTC** (time_source=1): validated via OSF bit at boot
2. **Zigbee sync** (time_source=1): `on_time_sync` writes to RTC hardware (60s cooldown); RTC poll skipped when ZB connected
3. **NVS saved epoch** (time_source=2): 10s deferred fallback; `nvs_seed_active` flag prevents echo being treated as ZB sync

### Schedule Execution
- 1-min `on_time` trigger; checks all 4 schedules (irr1, irr2, short1, short2)
- Guards: `boot_decision_ran`, `time_synced`, io_fault, maintenance

### Daily Reset (midnight on_time)
- `daily_water_time_sec = 0`, `scale_reset_day_counter++`
- Stale paused cycles cleared if not running
- `zone_start_counter = 0`
- `global_preferences->sync()`

## Safety Features

### Overwatering Protection (zone_start_counter)
- Counts `powerloss_resume` attempts on the same zone (restore_value: yes)
- At ≥ 3 attempts: skip zone, advance to next valid zone or next repeat pass
- Counter resets on: zone advance (normal end), manual skip, abort, fresh cycle start, midnight
- Prevents infinite overwatering loop from repeated power loss on the same zone

### Scale=0% Protection
- `zone_irr_duration_sec()` / `zone_short_duration_sec()` return 0 when scale=0% and scale_enable applies
- `start_cycle_actual`: checks `zone_queue_size > 0` BEFORE writing NVS state; aborts + clears state on 0
- Boot decision tree: discards missed c1/c2 before decision matrix if no valid zones
- `do_start`: checks valid zone count before any state write; returns silently if 0
- `powerloss_resume`: zone resolution loop skips zero-duration zones

### Pump Lockout (pump_lockout_sec)
- Mandatory cooldown after cycle end; prevents rapid pump restart
- B1 on PAGE_LOCKOUT: skip lockout, push ZB lockout cleared, update RGB, restart cycle

## Known Issues & Limitations

### Active
- B6: DS3231 OSF occasional false positive on warm reset
- B7: Cold boot ZB sync timing edge case
- B8: Stale ZB state window between powerloss and coordinator rejoin
- B11: 15-zone APS table requires manual edit to cached external component (lost on cache clear)
- `flash_write_interval=10s`: final value pending NVS lifetime analysis (S2)

### No Fix
- `cycle_remaining_sec` 1s drift on consecutive skips (cosmetic)
- Manual zone timer-expiry with negative stop offset: no drain delay (structural limitation)
- Forward jump remaining time drift (extreme edge case)
- pump_start_offset > zone_duration interaction (unrealistic config)

### Functional Limitations
- WiFi AP OTA mode: not supported (ESP32-C6 PMF/coexistence issue)
- `zb_network_switch`: stub only; full implementation deferred
- No rain sensor, flow meter, or weather API integration
